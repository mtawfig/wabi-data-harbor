## Typography and direction
- English: Inter (self-hosted via `@fontsource/inter`, weights 400–700), LTR.
- Arabic: IBM Plex Sans Arabic (self-hosted via `@fontsource/ibm-plex-sans-arabic`), RTL. `html[lang='ar']` swaps `--wi-font`.
- `LanguageService` sets `<html lang dir>` and persists the choice (`wi.lang`); after sign-in the account's preferred language applies. The root component wraps the router outlet in the CDK `dir` directive so Material layouts re-flow on runtime switches.
- Layout uses logical properties (`margin-inline-start`, `inset-inline-start`) so no per-direction overrides are needed. Icons that imply direction get `.wi-flip-rtl`.

## Phones: list tables as cards (P13.43)
- Up to 720 px wide, every list table (`table.mat-mdc-table`, `table.plain`, `table.matrix`) is shown as cards instead of a squeezed or sideways-scrolling table: a row is a block, a cell is a line with the column's name in front of its value, the first named cell is the row's heading (full width, bold), and cells without a column name (row actions) sit at the end of the card. Wider screens keep the table exactly as it was.
- The rules are global, in `src/styles.scss`; a page needs no change of its own. `ResponsiveTablesService` (`core/ui`, started once with the application) copies each header's text onto the cells of its column (`data-label`), marks the row's heading (`data-cell="title"`) and restores the table roles (`table`, `row`, `columnheader`, `cell`) that a table loses for assistive technology once it is laid out as blocks. It follows the page: rows added later and a language switch are labelled again.
- The header row is hidden from sight only (still read by screen readers). The layout properties are `!important` on purpose: they have to win over each page's own, more specific, table styles.
- Opt out with the class `wi-table-keep` on the `<table>`. Answer result tables (`.ask__table`) are data grids, not lists: they keep their sticky header and scroll sideways.
- Also on phones: cards have 16 px padding; in a filter row above a list (`.filters`) a field fills its row and may shrink to it (one per row on a phone, two or three on a wider one), so a search box is never wider than its card and a long placeholder never runs under the field's icon; a dialog's content may use the height of the screen (Material stops at 65%); an icon beside text never shrinks (`.mat-icon { flex-shrink: 0 }`, all widths), so long text cannot cover or clip it; the resting label of a field ends in "…" before the field's trailing icon instead of running under it (all widths: Material leaves that room only when the field also has a leading icon); the search box of a filter row (the field with a trailing icon) takes the room the other filters leave on its line (all widths); the analysis page keeps *Favorite*, *Share*, *Export* and *Re-run* visible and moves *Collections*, *Email*, *Archive* and *Delete* into a **More** menu; the Profile page's language button shows the language's name (`[full]="true"` on `app-language-switcher`), not the header's compact globe.

## Charts (P3.2)
- ECharts 6 through `ngx-echarts` (`provideEchartsCore` with a lazy `import('echarts')` so the chart runtime loads only with the dashboard chunk).
- `shared/ui/chart-theme.ts` holds the palette (`CHART_COLORS`: ocean, aqua, navy, amber, red, grey) and `baseChartOption(rtl)`: brand fonts, navy tooltips, light grid lines, animation off (deterministic screenshots), and in RTL the category axis is inverted and the value axis moves to the right so time still reads in the writing direction.
- KPI cards (`.kpi`) show counts in ocean; failure counters (failed sign-ins, email failures, API errors) in amber. Metrics the backend reports as `collected = false` are never drawn as zeros; they appear as chips under “Metrics arriving with later phases”.

## Support desk (P4.2)
- `features/support/` is shared by both areas: every page takes an `area` input (`app` | `platform`) from route data and calls the matching API prefix. Chips (`app-ticket-status`, `app-ticket-impact`, `app-ticket-type`) carry stable colours per code; the platform reads "Waiting for user" where the requester reads "Waiting for you".
- Ticket details use `mat-tab-group` inside a `.wi-card` with zero padding; the Activity Timeline is a connected vertical list (`.timeline` with an inline-start rule and circular icon nodes) that mirrors correctly in RTL through logical properties.
- The shell header shows a notification bell with a `matBadge` unread count (red), refreshed on load and every minute; clicking opens the area's notification centre.

## Translations
Transloco with `public/i18n/en.json` and `public/i18n/ar.json`. Keys are grouped by area (`common`, `landing`, `login`, `changePassword`, `bootstrap`, `nav`, `ask`, `platform`, `platformDashboard`, `health`, `audit`, `platformAdmins`, `organizations`, `admin`, `support`, `notifications`). Status codes and error codes from the API are mapped to keys (`login.errors.<code>`, `changePassword.errors.<code>`); codes themselves are never shown.

## "How this was computed" and the language switch (P13.11)
- The answer's *How this was computed* panel lists the assumptions, then each query as a definition list (*Data from*, *Calculated*, *Grouped by*, *Only rows where*, *Only groups where*, *Sorted by*, *Rows*) built from the validated plan and the catalogue's display names; never SQL, tokens or cost. On phones the list stacks (label above value). In Arabic, names and codes without an Arabic display name are wrapped in Unicode isolates so they stay whole inside the sentence.
- `app-language-switcher` names the language it switches to. Up to 600 px (`COMPACT_SWITCHER_QUERY`) it is a globe-only icon button, the same 40 px button as the header's bell, aligned with the other header icons (the target language is its accessible name and tooltip); larger screens keep the outlined pill with the language name. Shells must not restyle its internals.

## Dates and numbers (P13.10)
- Templates format dates with `| wiDate: 'medium' | 'mediumDate' | 'short' | 'shortDate' | 'shortTime'` and numbers with `| wiNumber: '1.0-2'` (`shared/format/locale-pipes.ts`), never Angular's `date`/`number` pipes, which follow the build locale only. In Arabic they use `ar-EG`: month names ("٨ نوفمبر ٢٠٢٦") and Arabic-Indic digits with Arabic separators, the same convention as answer tables; in English they give the same text as the Angular pipes of the same names.
- Numbers passed to translations (`{{count}}`) are formatted by `LocalizedTranspiler`: Arabic digits in Arabic, grouped from 10,000 so years and versions read naturally; English text is unchanged. Raw counts in templates go through `wiNumber`; codes (reference numbers, employee numbers) stay as text.

## Dashboard answers (P8.3)
- An answer is one or more panels. The answer card keeps the narrative and highlight list on top, then a note with the number of read-only queries that ran, then: a row of KPI cards (`auto-fit`, minimum 180 px, 34 px ocean value, muted label = panel title), a two-column chart grid (one column under 900 px; a single chart takes the full width; a second category column becomes grouped bars or several lines with a bottom legend; month-truncated dates are shown as `YYYY-MM`), and the detail tables with the panel title and row count (column aliases rendered as words).
